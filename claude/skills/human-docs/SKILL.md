# 人が読むドキュメントの書き方

AI が書いた文書は、人には読みにくいことが多い。このスキルは、ユーザーが繰り返し出してきた直しの指示を決まりとして貯め、毎回同じ品質で書くためのもの。

決まりは使いながら増やす。最初から完全ではない。

## ファイル

| ファイル | 中身 |
|---|---|
| `rules.md` | 書き方の決まり。直しを受けるたびに増える |
| `terms.md` | 言葉の言い換え表。直訳調の言葉と、使ってほしい言葉 |

どの使い方でも、最初にこの 2 つを全部読む。

## 使い方は 3 つ

| 使い方 | いつ | 入力 | 向いているモデル |
|---|---|---|---|
| `rewrite` | 既にある文書を見やすくする | 文書のファイル | 軽いモデルに任せてよい |
| `new` | 文書を 1 から書く | 書く内容の材料 | メインのセッションのモデル |
| `learn` | ユーザーが文書を直した、または直しを指示した | 直す前と後 | メインのセッションのモデル |

引数がないときは、状況から選ぶ。文書のファイルを渡されたら `rewrite`、材料だけなら `new`。

### rewrite：既にある文書を書き直す

内容は変えず、書き方だけを変える。

1. `rules.md` と `terms.md` を読む
2. 文書を読み、決まりに合わない所を洗い出す
3. 書き直す。事実・数値・決定・リンク・ファイルのパスは足さず、削らない
4. 図が要る所は、`rules.md` の図の決まりに従って作る
5. 下の「仕上げの確認」を通す
6. 何を変えたかを、決まりごとに短く報告する

軽いモデルのサブエージェントに任せるときは、次を依頼に書く。

- このスキルのフォルダーのパスと、`rules.md`・`terms.md` を先に全部読むこと
- 対象のファイルと、書き出し先
- 内容は変えないこと。意味が分からず言い換えられない所は、そのまま残して報告すること

戻ってきたら、メインのセッションで元の文書と見比べ、内容が落ちていないかを確かめる。

### new：1 から書く

何を書くかを決めるのは、文脈を持っているメインのセッションの仕事。軽いモデルには任せない。

1. `rules.md` と `terms.md` を読む
2. 読む人と、読んだ後にしてほしいことを決める。分からなければユーザーに聞く
3. 見出しの並びだけを先に作る
4. 決まりに従って本文を書く
5. 「仕上げの確認」を通す

長い文書で、内容を先に固めたいときは、下書きを書いてから `rewrite` にかけてもよい。

### learn：直しから決まりを育てる

ユーザーの直しは、その文書だけで終わらせず、次から同じ直しが要らないようにする。

きっかけは 2 つ。

- 会話で直しを指示された。例：「ここはバージョンと書いてほしい」
- ユーザーがファイルを自分で直した。引数でファイルを渡されるか、「直したので取り込んで」と言われる

手順：

1. 直す前と後を集める
   - 会話の指示なら、指示の文と、直した所の前後
   - ユーザーが直したファイルなら `git diff` で差分を取る。Git で追えないときは、直す前のものをユーザーに求める
2. 直しを 1 件ずつ分け、それぞれ次のどれかに振り分ける
   - **言葉の言い換え**：`terms.md` に足す
   - **書き方の決まり**：`rules.md` に足す。既にある決まりの例になるなら、その決まりに例を足すだけにする
   - **その文書だけのこと**：内容の間違いや、その題材だけの事情。スキルには足さない
   - **判断がつかない**：`rules.md` の「まだ一般化していない直し」に、そのまま書き留める
3. 一般化の案を作る。1 件ごとに「直しの実例 → 決まりの文 → 当てはまる範囲」を並べる
   - ユーザーが言ったことより強い決まりにしない。1 件の直しから「常に」「禁止」を作らない
   - 題材や作品の名前など、その文書だけの値を決まりに入れない
   - 既にある決まりとぶつかるときは、どちらを残すかをユーザーに聞く
4. 案をユーザーに見せ、承認を得てからファイルを書き換える
5. 「まだ一般化していない直し」に似たものが 2 件以上たまっていたら、まとめて決まりにする案を出す

このスキルで文書を作ったセッションの中で直しを受けたら、言われなくても、区切りで `learn` の案を出す。

## 仕上げの確認

書き終えたら、文書を頭から読み直して確かめる。

- `rules.md` の決まりを 1 つずつ当てたか
- `terms.md` の左の列の言葉が残っていないか
- `rewrite` のとき：元の文書の事実・数値・リンクが全部残っているか

## このスキル自体の書き方

`SKILL.md`・`rules.md`・`terms.md` もユーザーが読むので、同じ決まりで書く。
